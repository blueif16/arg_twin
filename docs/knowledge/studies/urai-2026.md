# URAI: agents write tools, then decide between tool calls (2026)

`[urai-2026]` · Ge, Zhou, Zeng et al., "Make Code as Policy Great Again", arXiv 2609.39018 · status: verified · local: `data/refs/urai-2026.html`

Read 2026-10-24 from the arXiv HTML. Every number is theirs. Lines starting "For us" are our reading.

## Setup

- A programming agent (Claude Fable 5.1 in Claude Code) writes reusable and task-specific tools from task intent and refines them with execution feedback and human guidance. Validated tool revisions persist across episodes.
- A frozen execution agent picks and parameterises tools from current observations. Each tool call runs a full multi-phase motion locally, then returns control.
- Three decision boundaries compared: direct control (model picks every end-effector command), code as policies (a generated program makes the later decisions), URAI (model decides between tool executions).
- Five RoboDojo tasks in simulation, same step budgets and a 100-command limit in both conditions; seven real AgileX dual-arm tasks.

## Results

- Success, URAI vs direct fingertip control: Fable 5.1 52 vs 16%, Opus 5.5 60 vs 32%, GPT-6 Astra 52 vs 16%, DeepSeek-V4-Flash 48 vs 8%. Aggregate **53.0% vs 18.0%**.
- Same tools, **a program written in advance reaches 24%; two agents deciding after each call reach 56%.**
- Three of four agents finish 1.3–1.5× faster with 1.5–1.7× fewer execution-agent output tokens; DeepSeek-V4-Flash's cost barely changes.
- Real robot: tic-tac-toe 3/3 games at 5.0 min, 37 model calls and 3.26k output tokens per game, 2.7× faster than a published step-by-step baseline with the same model.
- Few episodes per cell; the authors limit their claim to this tool collection and task mix.

## For us

- Supports task-level tools (`insert(part, hole, max_force)`) over raw pose output, with numbers.
- It also argues against compiling the decisions themselves too early: the pre-written program lost 56 → 24. Our compile step should promote motion routines first and keep Argon at the branch points until held-out starts show the routine's own checks are enough.
- Tool revisions are versioned and persisted; their GUI/API is shared by humans and agents, like our harness registry.
