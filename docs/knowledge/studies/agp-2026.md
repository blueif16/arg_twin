# Agent as Policy (AGP): a coding agent drives a real arm (2026)

`[agp-2026]` · Jia, Lin, Zhang et al., arXiv 2609.12541 · status: verified · local: `data/refs/agp-2026.html`

Read 2026-10-24 from the arXiv HTML. Every number is theirs. Lines starting "For us" are our reading.

## Setup

- A general-purpose agent (Codex or Claude Code) is the policy for the whole episode. It sees camera images and robot state, writes and runs its own scripts, requests motions, and decides after each result. A separate preparation agent turns instructions, goal images or demo videos into the task context.
- Real I2RT YAM arm with a parallel gripper; towel folding uses two arms. Assembly parts are adapted from the AutoMate dataset (insertion of rings, collars and posts).
- Fixed budgets on time and on observation and action requests. Success judged on physical outcome.

## Results (GPT-6 Astra unless noted)

| Task | Success | Time per success | Tokens per success | Cost |
|---|---|---|---|---|
| Four-pair assembly (video demo) | 8/10 | 37.2 min | 13.02M | $16.62 |
| Pyramid / two towers / six-block tower | 10/10, 10/10, 9/10 | 21.6, 20.6, 28.2 min | 9.24M, 7.94M, 11.57M | |
| Dice flipping | 10/10 | 37.9 min | 17.08M | $21.07 |
| Targeted throwing | 9/10 | 17.7 min (session) | 5.71M | |
| Towel folding: sequential / simultaneous | 5/5, 3/5 | 50.8, 21.4 min | 18.12M, 5.06M | |

- At least 80% success in 7 of 8 configurations, 100% in 4.
- Baselines on the same tasks: two-pair assembly AGP 5/5, ASPIRE 2/5, Graph-as-Policy 0/5. Four-pair: AGP 8/10, both baselines 0/10.
- Works with both Codex and Claude Code. Astra succeeded on two-pair assembly at low, medium and high effort; GPT-5.6 Terra and Luna struggled; Fable 5.1 had lower success than Opus 5.

## Experience reuse

- **Refinement:** Astra repeats a task 5 times; each run reads and updates saved documents (part heights, grasp and insertion settings, corrections, scripts). Runtime falls across runs, mostly in "reasoning and programming" time; tool execution time stays flat or rises slightly. Motion requests fall from 37 to 32 (ring task) and 25 to 23 (two-pair).
- The authors state the refinement sequence is uncontrolled (object positions change between runs); a comparison starting each trial from empty experience is still needed.
- **Transfer to a weaker model:** GPT-5.6 Terra with Astra's frozen documents goes from 1/5 to 4/5. On successes, time 19.0 → 12.5 min (−34.3%), tokens 6.28M → 5.56M (−11.4%).

## For us

- This is the closest published setup to ours: an agent at the decision points, insertion-type assembly, experience written to files. It is real-robot, not twin, and n is 5–10 per cell.
- Token savings from experience were small (−11%) while time savings were larger (−34%). Our "tokens per success fall" claim needs the larger lever: compiled code that runs without the brain (see `rax-2026`), not documents alone.
- Experience documents carry task knowledge across models. This is why an Argon run must start from an empty learned-skill library.
- Their accounting (tokens incl. reasoning and cached input, time split into reasoning vs tool execution) is a good template for our call log.

## Limitations (checked 2026-10-24)

- The paper notes that its timings "do not isolate" the benefit of parallel arm motion (§D.1). It also notes that isolating experience reuse would need trials that each start with empty experience (§D.2).
- The broader claim that AGP doesn't separate runtime programming from model, calibration, controller and interface design reached us secondhand. The paper doesn't state it in those words, but its experiments do vary these factors together.
- For us: the baseline vs attempt-N comparison holds the model, calibration, controller and interface fixed, so the difference measures what practice and compilation add.
