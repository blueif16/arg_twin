# build-twin: mujoco

The v1 skill `mujoco`, moved here unchanged by skills-v2 (archived at `playbook/archive/skills-v1/mujoco/SKILL.md`; only skill names and paths are updated to where their content now lives). v1 description: How any agent builds, compiles, steps, renders and checks MuJoCo models in this repo (MuJoCo 3.17 + MuJoCo Warp): naming and frame conventions, sites as task frames, collision modelling for tight holes, contact parameters, the halved-timestep check, Warp usage and gotchas, and which outside models and meshes to use.

## Goal

Any model you add or change:

- **compiles**;
- **round-trips through MJCF**: a written file reloads to the same masses, sizes, poses and numerics;
- **settles under gravity** with no NaN and with resting penetration below 0.1 mm;
- exposes its **task frames as named sites**;
- **gives the same answer at half the timestep.**

A watcher should be able to check all of this from the MJCF file and the tool outputs alone.

## Inputs

- `twin/scene/base.xml`: FR3, Franka hand, table, the cameras `hand`/`hama1`/`hama2`/`overview`, the `tcp` site and the keyframe `reassemble_start`. It is generated by `twin/scene/build_base.py`; see `docs/research/env-setup-notes.md`.
- The sim package `twin/`:
  - `assembly.py`: scene build, check and render
  - `board.py`, `parts.py`, `layout.py`: the board and its parts
  - `predicates.py`: success, read from sim state
  - `probe.py`: insertion probe
  - `warp_check.py`: GPU vs CPU comparison
  - `render.py`, `warp_bench.py`
- Environment: `.venv` (Python 3.12) with mujoco 3.17.0, mujoco-warp 3.17.0, warp 1.18, trimesh 5.2, coacd, scipy and matplotlib. **No shapely**, so trimesh's polygon helpers fail; slice meshes with `mesh.section(...).discrete` instead.

## Approach

### Conventions (an interface: renaming needs a version bump, rules.md)

- **Units and frames.**
  - Units are SI (m, kg, s). base.xml uses `angle="radian"`.
  - The world frame is the FR3 base (link0). The table top is at z = 0.
  - MuJoCo quaternions are **w-first**; mocap JSON is `[qx,qy,qz,qw]`. `twin.assembly.resolve_board_pose` accepts both.
- **Names.**
  - Part slug: `twin.layout.slug(name)`, for example `round peg 1` → `round_peg_1` and `D-SUB` → `dsub`.
  - Bodies: `board`, `<slug>`.
  - Geoms: `board/plateNNN`, `<slug>_hole/wallNN`, `<slug>/collision`.
  - Joints: `<slug>/free`.
- **Sites as task frames** (group 4):
  - `<slug>_hole/entry`: the hole centre on the surface. **+z points into the hole** (the insertion direction); +y runs along the hole's long side.
  - `<slug>_hole/bottom`: where the part stops.
  - `<slug>/tip`: the leading end of the part. +z is the insertion direction; +y is the finger-closing axis.
  - `<slug>/grasp`: where the fingers hold the part, same axes as `tip`. Putting the gripper's TCP frame on `grasp` is the grasp pose.
  - When a part is seated, `tip` coincides with `bottom`. Code turns relations between these frames into poses, and never hard-codes coordinates.
- **Evaluator data lives in the MJCF** as `<numeric>` entries: `<slug>/seat_depth`, `<slug>/clearance` and `<slug>/tol`. `twin/predicates.py` needs only the model and the state.

### Build, compile, step, render

- **Build with `mujoco.MjSpec`**, not XML string templates. Load with `MjSpec.from_file(base.xml)`, edit, then `spec.compile()`. Write with `spec.to_xml()` and always reload the file and compare arrays (`twin/assembly.py` checks `body_mass`, `geom_size`, `geom_pos`, `site_pos`, `body_pos` and `numeric_data`).
- **`to_xml` quirks in 3.17:**
  1. Menagerie mesh paths are relative to `twin/scene/`. Re-root them when the file is written elsewhere (`_fix_xml`).
  2. `mass="0" density="0"` disappears from the FR3 collision default. Restore it with the regex in `build_base.py`/`assembly.py`.
  3. Attaching with an empty prefix writes an unnamed `<default>` that will not reload.
  4. Adding free bodies changes `nq`, so rewrite every keyframe's `qpos`/`qvel` (`build_scene` appends `qpos0` of the new joints).
- **Meshes from vertices:** `mesh.uservert = verts.ravel()`. MuJoCo builds the convex hull, so a chamfered peg needs no file.
- **Step loop:**

  ```python
  m = mujoco.MjModel.from_xml_path(xml)
  d = mujoco.MjData(m)
  mujoco.mj_resetDataKeyframe(m, d, key)
  mujoco.mj_step(m, d)  # repeat
  ```

  - **Set `mjDSBL_AUTORESET`** (or watch `d.warning[mjWARN_BADQACC]`). Otherwise MuJoCo silently resets a diverged state, and a `while d.time < T` loop never ends (it happened: probe v0).
- **Render:**
  - Rendering needs `MUJOCO_GL=glfw` (`egl` fails, `osmesa` is not installed).
  - Use `with mujoco.Renderer(m, h, w) as r: r.update_scene(d, camera=..., scene_option=opt)`.
  - Enable `opt.sitegroup[4] = 1` to see task frames.
  - Raise `m.vis.global_.offwidth/offheight` for big images.
  - Coplanar overlapping boxes z-fight. `board.py` sinks the hole walls 20 µm below the plate top.
- **Contacts and forces:**
  - `d.contact[:d.ncon]` gives `dist < 0` for penetration.
  - `mj_contactForce` returns the force in the contact frame; rotate it with `frame.reshape(3,3).T`. The result is the force on geom2.
  - See `twin.predicates.contact_force_on`.

### Collision modelling for tight holes

A convex hull cannot have a hole. The options below were measured on round peg 1, a 4.0 mm peg in a 4.1 mm hole (0.05 mm per side):

| Method | Precision | Cost | Warp | Use for |
|---|---|---|---|---|
| **Compound primitives**: one box per wall edge. A round hole is an N-gon whose flats sit at the hole radius (`twin/board.py`). | Exact flats. Vertices sit up to r(1/cos(π/N) − 1) further out: +0.01 mm for r = 2 mm at N = 32. | ~0.1 s compile. A probe takes 0.02–0.1 s wall per 1–1.5 s simulated. | yes (box–mesh/box–box) | **every hole whose fit matters** |
| Convex mesh hull from `uservert` | Exact for convex parts | cheap | yes | pegs with chamfers; any convex part |
| Primitive cylinder or box peg | exact | cheapest | yes | unchamfered pegs |
| coacd convex decomposition | Hull pieces bridge small gaps, so holes close up | many geoms | yes | outer shapes of connectors and housings, not fits |
| **Mesh SDF**: `mesh.needsdf=True`, geom type `sdf`, octree, no plugin. **Supported in 3.17 on CPU.** | With the default octree (64k cells) the hole behaved as if loose: a 0.0725 mm offset (past the 0.05 mm clearance) still went in. At `octree_maxdepth=9` (4.3 M cells) the same offset jams correctly. | 0.14 s compile by default, 13–15 s at depth 9 | coded (volume SDF), not tested here | odd shapes where primitives are impractical; check with the probe |
| SDF plugins `mujoco.sdf.{gear,nut,bolt,torus,bowl}` (bundled in `mujoco/plugin/libsdf_plugin.so`) | parametric | gradient-descent contacts | **no**: Warp's `user_sdf` is an unimplemented stub | gear meshing and threads on CPU only |

### Contact parameters and timestep

- **Board and part defaults** (`twin/board.py: CONTACT`):
  - `solref=[0.004, 1]`
  - `solimp=[0.95, 0.99, 0.0005, 0.5, 2]`
  - `margin=0`, `condim=3`, pyramidal cone
  - board friction 0.05, so MuJoCo's max rule hands each part–board pair to the part's own `friction` parameter
- **Fix `timeconst`; never use the 2·dt default.** That way the halved-timestep check compares the same physics. `refsafe` clamps `timeconst` to ≥ 2·dt, so 0.004 works for dt ≤ 2 ms.
- **MuJoCo's default contact (`solref 0.02`, `solimp 0.9/0.95/1 mm`) is unusable for 0.05 mm fits.**
  - A 4×4 key overlapping the rim by 0.024 mm slid 5.7 mm into the hole.
  - It did so at every dt, so the dt/2 check passed it.
  - Only the probe's geometric expectation caught it (`runs/scene/experiments/contact_params.log`).
- **Use dt = 1 ms for insertion work.** base.xml's 2 ms pushed a 0.024 mm rim overlap 1.0 mm too deep, while 1 ms and 0.5 ms agreed with geometry to 0.02 mm. `scene_build` and `insertion_probe` default to 1 ms.
- **Precision floor ≈ resting contact penetration** (0.01–0.04 mm at 10 N with these parameters).
  - Interference smaller than that gives timestep-dependent depths, even though the outcome (jam vs seated) stays the same. An example is sampled world 3, which has a 0.0188 mm overlap.
  - Keep fit tests at ≥ 0.04 mm interference, or use dt ≤ 0.5 ms.
- **Impact penetration is set by `timeconst`, not by dt.** Dropping pegs into their holes from 10 mm gave 0.59 mm transient penetration (0.84 mm at dt/2) but 0.0001 mm at rest. `scene_check` reports transients as warnings and resting penetration as problems.
- **Flat end on a rim edge.** An unchamfered peg overlapping the rim by 0.0225 mm stops 0.27 mm deep instead of at 0. Once the tip sinks past the overlap, the contact normal turns sideways and only friction holds the peg. The outcome is right; the depth is off by about 0.3 mm.
- **Stiff servos and springs** are explicit in the integrator: keep ω·dt < ~0.5, where ω = √(k/m_eff).
  - A 2e5 N/m servo on a 15 g rig diverged at dt = 2 ms.
  - Add `armature` (m ≥ k·(dt/0.5)²) or drop the joint entirely ("rigid").

### The halved-timestep check (rules.md)

1. Re-run the same scene or probe with `m.opt.timestep /= 2`.
2. Compare outcomes and key numbers: final part positions (< 0.5 mm), seated flags, and probe outcome plus depth (< 0.5 mm).
3. `scene_check` and `insertion_probe` do this by default (`halved_timestep: true`).
4. Disagreement means integrator error. Agreement is necessary, not sufficient: see the default-contact case above.

### MuJoCo Warp

- **Basic use:**
  - `m = mjw.put_model(mjm)`
  - `d = mjw.put_data(mjm, mjd, nworld=N, nconmax=..., njmax=...)`. **Both are per world**; `naconmax` is the total.
  - Capture `mjw.step` in `wp.ScopedCapture()` and launch the graph.
  - `d.nacon` counts contacts over all worlds.
- **First JIT and cache.** The first JIT of a new model took 18 s for the board scene (89 s for base.xml in the env notes). After that, the kernel cache in `~/.cache/warp/1.18.0` brings it to about 1.5 s.
- **float32.** Positions near 0.5 m have about 0.06 µm resolution, which is fine for 50 µm fits. World 0 matched CPU to 0.0001 mm in depth (`runs/scene/pegs_above_1ms/warp_check_n1024.json`).
- **Not supported:**
  - SDF plugins (gear/nut/bolt)
  - body, actuator and sensor plugins
  - contact sensors with linvel/angvel
  - noslip with the discrete integrator (`mujoco_warp/_src/io.py`)
- `mjwarp-testspeed` needs `--overflow_behavior continue` when control noise is high.

## Checks

A watcher runs these from files and tool outputs only:

1. `scene_check {xml}` → `ok: true`, `problems: []`, `settle.final_penetration_mm ≤ 0.1`, and `halved_timestep.seated_agrees` all true.
2. Reload test: `mujoco.MjModel.from_xml_path(xml)` compiles, and every site named in the interface above exists for each part listed in `params.json`.
3. `insertion_probe {part}` → `geometry_ok: true` and `half_dt_agrees: true`.
4. For GPU use: `python -m twin.warp_check --xml <scene>` → `nan_worlds = 0` and `max_depth_diff_vs_cpu_mm < 0.05`.

## Lessons

**2026-10-24, claude-opus-5.5 stand-in (caller `build-twin-dev` in `runs/calls/20261024.jsonl`).** Evidence: `runs/scene/experiments/*.log`, `runs/scene/probe_campaign_20261024_final.txt`, `runs/scene/pegs_*/`.

- **Primitive holes work as intended.**
  - Of 64 nominal probe runs (8 pegs × stiff and compliant × 4 offsets), every one matched geometry. Each run also agreed with its dt/2 re-run.
  - In 7 of 8 parts, jam depths sat within 0.02 mm of the geometric value (chamfer − (offset − clearance)).
  - Probe evidence: `runs/scene/probe/*_20261024-1735*.json`.
- **Contact defaults:** see "Contact parameters and timestep". MuJoCo's defaults failed silently; dt = 2 ms failed visibly through the dt/2 check.
- **Mesh SDF:** CPU works, but resolving 0.05 mm took octree depth 9 and 14 s of compile time (`sdf_hole.log`). Prefer primitives.
- **Warp scale:** 1024 worlds, each dropping 8 pegs into their holes, ran 1000 steps at dt = 1 ms in 3.0 s: 337 k steps/s. All 1024 worlds seated every peg. CPU ran one world in 0.15 s. `warp_check_n1024.json`.
- **Probe v0 hang:** the run diverged and auto-reset, and the time-based loop never ended. Fixed by disabling `AUTORESET` and adding armatures (`twin/probe.py`).
- **Render artefact:** the light rosettes around holes in `board_top` renders are the hole-wall tops. They are cosmetic, but overlay agents should mask them or not rely on hole-region pixel colour.
- **2026-10-24** (claude:b2-replay): Replaying a real arm (B2): torque-controlled FR3 in MuJoCo. Turn the menagerie position actuators into motors (set_to_motor, ctrlrange +-87/+-12 Nm) and set body gravcomp=1 on fr3_link* and gripper/* to stand in for the firmware's gravity compensation; leave the held part uncompensated, since the real wrist sensor sees its weight. Set the menagerie joint frictionloss (1.137 Nm on joints 1-4) to 0 when the setpoint is rebuilt from logged state: the rebuilt target already contains the real arm's friction. Keeping it took the free-space tracking error from 0.73 to 5.1 mm. In 3.17 the dense mass matrix is mj_fullM(m, d, dst); d.qM is gone. Evidence: `runs/claude/run-standin-1/replay/free_space_check.json`, `twin/replay.py`, `twin/control.py`.
- **2026-10-24** (claude:b2-replay): Grasping with contacts so the part can be released by the logged gripper. Put the part as a free body between the pads and find the finger opening where the pads just touch by bisecting mujoco.mj_geomDistance; starting with a gap lets the part fall during the close. Drive the finger tendon with a position servo whose target is past contact (-0.03 m), so forcerange (2x grip force per finger, tendon coefficient 0.5) sets the squeeze and kp does not. Pre-roll 0.25 s before t = 0. Give the pads condim 4 (torsion resists pivoting about the closing axis) and give the part a near-zero torsional coefficient, because MuJoCo's max rule would otherwise let the part's 0.005 own the pads' torsion. A joint-chain grasp (hinges with frictionloss) cannot release, and its default solreffriction 0.02 let a held part creep 2 mm in 1.3 s; set solref_friction to 2 dt if you use one. Evidence: `twin/replay.py`, `runs/claude/run-standin-1/replay/final_train_frozen.json`.
- **2026-10-24** (claude:b2-replay): dt/2 and cost for replays. 48 compliant peg replays (contact grasp, elliptic cones, impratio 10, Newton at tol 1e-10, dt 1 ms with the controller at 1 kHz) gave 48/48 identical outcomes at dt 0.5 ms; median peak-force difference 0.5 N, p90 3.6 N. The Python controller costs ~0.4 ms per tick with the manipulability gradient refreshed every 10 ticks (1 ms when refreshed every tick, same tracking). A multiprocessing pool of 15 replays 308 windows in about 2 min, enough for identification sweeps on CPU. Warp batches need the controller as a kernel, or a Cartesian impedance rig, first. Evidence: `runs/claude/run-standin-1/replay/final_train_dt05.json`, `runs/claude/run-standin-1/replay/free_space_check.json`.
- **2026-10-24** (claude:b2-replay): Torque-controlled arm replays: Cartesian impedance nullspace potentials ring without joint friction. REASSEMBLE's joint-limit potential (tanh wall, gain 10) gives several Nm once FR3 |q2| > ~1.2 rad. With menagerie's joint frictionloss removed and nullspace damping 0.1, that ringing went undamped and leaked into the EE through the kinematic projection: free-space RMSE up to 434 mm in a few windows. Dropping the potentials (ns_jl = ns_manip = 0) gave median 0.99 -> 0.65 mm, p90 4.1 -> 1.8 mm, max 17 mm over 303 windows. Extra joint damping (1 Nms) alone did not fix the tail (max 225 mm). Evidence: `runs/claude/run-standin-1/replay/free_space_v2.json`, `runs/claude/run-standin-1/replay/free_space_features.json`.
- **2026-10-24** (claude:b2-replay): Hand frames: the logged Franka O_T_EE is a configured point, not the pad centre. In REASSEMBLE it lies 22.9 mm beyond the pads; base.xml now mounts the hand on a 47.7 mm stack and keeps the tcp site on O_T_EE. Hold or place parts at the pad centre (hand z 0.1034, the '<slug>/grasp' convention), never at the tcp site. With the old hand (pads on O_T_EE) the replay's peak-force error was 0.72 vs 0.36, and onset error 0.43 vs 0.23 s. Parallel-jaw pads hold a part's pivot about the closing axis (torsional friction) but not a rock about the pad-width axis: a pre-roll squeeze undoes any registered rock. Finger hinges at the pad centre with springref set to the registered angle (before t = 0) can hold it, plus an offset on the finger-coupling equality (q1 = q2 + 2 dy) to hold the part off-centre. Evidence: `runs/claude/run-standin-1/replay/train_v2_summaries.json`, `runs/claude/run-standin-1/replay/screen_newhand.json`, `twin/scene/build_base.py`.
- **2026-10-24** (claude:b2-replay): Part friction against tight holes after release: with friction 0.30 (elliptic cones, impratio 10) released pegs stuck 2-4 mm deep at 6-12 deg tilt where the real ones fell in. 0.15 seated more without losing as many jams (stratified train bacc 0.580 -> 0.645; 0.10: 0.616; 0.20: 0.609); impratio 1 gave 0.572. solimp width 0.5 vs 0.1 mm made little difference (0.529 vs 0.551). Its soft layer acts only at negative distance (margin 0), so it does not take up clearance. Evidence: `runs/claude/run-standin-1/replay/screen_newhand.json`.
- **2026-10-24** (claude:b2-replay): MuJoCo Warp for per-attempt particle filters (twin/rig.py, twin/pf.py). (1) Replace a Python per-tick controller by an equivalent Cartesian impedance rig (6 joints at the TCP; position actuators with kp = K and K_r/2, kv = diag(D), armature = diag(Lambda) minus subtree), so the whole controller runs inside mjw.step. One 10 s window takes 0.6-1.6 s per world on CPU. Peak force differs from the full-arm replay by up to 2x (diagonal Lambda/D), and Fz correlation with the real sensor is 0.49-0.94 on three attempts. (2) Per-world pre-t0 variation: put_model(mjm, batch_sizes={geom_friction, geom_pos, qpos_spring, eq_data: N}), then .assign() per-world arrays; per-world initial state goes through d.qpos.assign. (3) put_model rejects mjDSBL_AUTORESET: drop it and screen non-finite worlds yourself. Force/torque sensors are supported. Raise ls_iterations to 50. (4) Step latency dominates: 64 worlds ran a 10 s window in 18 s, 1024 worlds in 33 s, so take N = 1024. (5) GPU memory: about 3.5 GB per process at 1024 worlds with nconmax 96 / njmax 600. Three processes plus per-attempt models that were never freed ran out of memory, and the CUDA context then failed every later call (error 999). Free the graph, model and data per attempt and recycle the process every ~10 attempts. njmax 400 overflowed. (6) Make frames exact: dt = 1/990 s gives 33 steps per 30 Hz frame. Rounding 33.3 to 33 at dt = 1 ms drifts 0.1 s over 10 s. (7) Capture one frame of steps in a graph and interpolate ctrl inside it with a tiny kernel whose alpha is baked per step at capture time. Evidence: `twin/rig.py`, `twin/pf.py`, `twin/pf_batch.py`.
- **2026-10-25** (claude:b2-5b): Modelling a compliant parallel-jaw grasp (twin/replay.py v5b knobs). (1) Soft MuJoCo contacts are a poor pad model: raising the pad-part timeconst per part to match a measured squeeze compression collapses the opening through the part within one grid step (0.011 -> 0.015 s), and softness is mass-normalised (4 g pegs already compress 0.4 mm at 4 ms). (2) A rock hinge through each pad's own centre makes the two pads turn about different axes. A rigid part between them then shears the pads and keeps only one contact row on one side, which also halves pivot and slide resistance. Put both hinges on the part's axis (finger frame y = -w/2, pads 2-5 face at y = 0) and tie them with a joint equality (right = -left, since the right finger's x is flipped), so the pads stay parallel. (3) The twin's own pad contacts are in series with the hinge. Measure total grasp stiffness with a static load test (ramp xfrc_applied on the part while the controller holds the hand, subtract the unloaded drift) and correct k_hinge = 1/(1/k_target - c). (4) Code that loops over every mjEQ_JOINT to set the finger-coupling offset also writes into any joint equality you add: name yours and reset it after. (5) Hinge damping from a ratio on the real inertia (armature + finger + half the part) instead of 4 sqrt(k armature). Evidence: `runs/claude/run-standin-1/replay/fit_v5b.json`, `runs/claude/run-standin-1/replay/params_v5b.json`, `runs/claude/run-standin-1/replay/v5b/k_targets.json`, `runs/claude/run-standin-1/replay/v5b/char_v5b_k1.json`, `runs/claude/run-standin-1/replay/v5b/char_v3_all.json`, `runs/claude/run-standin-1/replay/v5b/ident_pads.json`, `twin/replay.py`.
